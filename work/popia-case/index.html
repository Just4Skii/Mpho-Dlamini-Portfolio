POPIA Platform

A data-protection enforcement workspace: complaint intake and evidence, case triage, a phone-number reputation desk, and an append-only audit log — built for POPIA workflows.

ASP.NET Core MVCEF Core + SQLiteIdentity 45 seeded complaintsSynthetic data

What is actually working

Complaint register

Intake with category, severity and evidence; triage, investigation and resolution states; 15 active cases in the demo account.

Offender tracker

28 public complaints and resolution stats, grouped by company and violation type.

Phone intelligence

Carrier, line type, region, spam reports and a risk band from a synthetic SA carrier database.

Audit

Every action is written to an append-only audit log tied to the actor and case.

How it was verified

  • Started from 72 compile errors: SQL Server migrations against a MySQL provider, with no database server available.
  • Migrated the project to a self-contained SQLite database, removed incompatible migrations and switched startup to schema creation.
  • dotnet build — 0 errors; app starts, creates the schema and seeds companies, complaints and demand letters.
  • Logged in as the seeded test account and exercised the dashboard, complaints register, offender tracker and a live phone lookup (0821234567 → low risk, Vodacom, valid, 0 reports).
Hosting note: this is a server-rendered ASP.NET application, so it is not embedded here. Run it locally with dotnet run --urls http://127.0.0.1:5000. Seeded login: test@example.com. Demonstration data only — not a legal finding and not connected to the Information Regulator.
